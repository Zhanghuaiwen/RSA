# 现代密码学课程设计报告

> 基于 RSA 与 ElGamal 的混合公钥密码系统、简单证书方案、PKI 与简易安全邮件系统

作者：课程设计小组  
日期：2026-08-24  
运行环境：Windows 10/11，MinGW64 g++ 9.2.0（`D:\Dev-Cpp\MinGW64\bin\g++.exe`），`-O2 -std=c++11`

## 1. 任务概述

依据 `README.md` 的要求，本设计实现如下内容：

1. 实现 **RSA** 加密/解密算法以及 RSA 签名/验证算法。
2. 实现 **ElGamal** 加密/解密算法以及 ElGamal 签名/验证算法。
3. 实现一种**简单证书方案**：证书需携带 `flag1`（签名算法：0=RSA、1=ElGamal）与 `flag2`（用途：0=加密、1=签名），证书以 **txt 文本** 形式保存。
4. 搭建一个**简易 PKI**：包含一个**根 CA** 与两个**下级 CA**（如 CA1、CA2），用户向 CA 申请证书；证书库支持按 ID 查询并向**根 CA** 回溯构建证书链，验证证书链。
5. 实现**简易安全邮件系统**：发送方用自己签名私钥对邮件签名，并用接收方加密公钥加密；接收方用自己的加密私钥解密，并用发送方签名公钥验证签名（结合证书链验证发送方身份）。
6. 随机素数 `p,q` 均为 **1024 比特** 长度（程序默认 512 比特以求演示速度，可在菜单“9. 切换密钥强度”中选 1024 即完全符合任务书要求）。

> 说明：目标机未安装 NTL 库，且无 make/sh/perl。为使代码采用 NTL 风格 API（便于阅读、且可后续直接链接真实 NTL），本报告**自行实现了一个 NTL 兼容的大整数类 `NTL::ZZ`**（含乘法/除法/模幂/扩展欧几里得/素性测试等），从而保证源码可直接在无 NTL 环境编译运行。

## 3. 核心算法设计

### 3.1 大整数库 `NTL::ZZ`
- 采用 32-bit 基（`base = 2^32`）的 `std::vector<uint32_t>` 存储，小端排列。
- 乘法 `mulMag`：Schoolbook，再对进位做规整；除法 `divmodMag`：Knuth 卷 2 算法 D（试商时以 `unsigned __int128` 比较避免溢出），解决了高位进位与试商上界两类关键错误。
- 模幂 `PowerMod`：从高位到低位的平方-乘；素性测试 `ProbPrime`：对 2/3/5 等小素数做试除后，进行 `k` 轮 Miller–Rabin。
- 密钥生成 `RandomPrime(bits, k)`：随机生成 `bits` 比特奇数，小素数试除加速，再行 Miller–Rabin（默认演示 `k=12`，任务书强度可设 `k=20`）。

### 3.2 RSA
- 密钥生成：`RandomPrime` 生成 `p,q`（`bits` 比特，满足 `p≠q`），`n=pq`，`φ=(p-1)(q-1)`，`e=65537`，`d=e^{-1} mod φ`。公钥 `(n,e)`，私钥 `(p,q,d)`。
- 加密：`c = m^e mod n`；解密：`m = c^d mod n`。
- 签名：`s = H(m)^d mod n`；验证：`s^e mod n == H(m)`。其中 `H` 为 SHA-256。
- 消息编码：字符串按小端打包成 `ZZ`；解密后按字节还原。当 `m` 较大（>模数）时采用分块（以 `|` 分隔各密文块）。

### 3.3 ElGamal
- 密钥生成：生成安全素数 `p=2q+1`，取 `g=2` 验证其为 `q` 阶生成元，私钥 `x∈[2,p-2]`，公钥 `y=g^x mod p`。
- 加密：`c1=g^k, c2=m·y^k mod p`（`k` 随机）。解密：`m=c2·c1^{-x} mod p`。
- 签名：`r=g^k, s=k^{-1}(H(m)-x·r) mod (p-1)`；验证：`y^r·r^s ≡ g^{H(m)} mod p`。

### 3.4 简单证书方案 `Cert`
字段：
```
ID      ：证书持有者标识
VER     ：持有者公钥（方案前缀 RSA/ELG + 公钥串）
SIG     ：颁发者用其私钥对 dataForSign() 的签名
ID_TA   ：颁发者（上级 CA / 根 CA，自签时为自身）
FLAG1   ：签名算法（0=RSA，1=ElGamal）
FLAG2   ：用途（0=加密，1=签名）
```
- `dataForSign() = ID + "|" + VER`。
- `issueCertificate`：用 `taPriv` 对 `dataForSign()` 的 SHA-256 摘要签名得到 `SIG`。
- `verifyCertificate(cert, issuerPub)`：用颁发者公钥重新计算 `H(dataForSign())` 并验证 `SIG`。
- 文本格式：`toTxt()` 产出上述字段的键值文本，可 `fromTxt()` 还原，满足“证书以 txt 文本保存”。

### 3.5 简易 PKI
- `CertRepo`：单例 `std::map<ID, Cert>` 证书库，提供 `addCert`/`getCert`/`getCertPath`/`saveAll`。
- `getCertPath(subjectID)`：从 `subjectID` 出发，沿 `ID_TA` 上溯到自签根 CA，返回链 `[root, …, subject]`。
- `verifyCertPath(path)`：自根向下，逐张用颁发者公钥验证下一张证书。
- `CA::initRoot`：根 CA 自签名（`ID_TA=自身`，`flag2=签名`）。`CA::initSub`：下级 CA 由父 CA 签发。
- `PKI::build`：建库（`clear` 后）生成根 CA，再由其签发 CA1、CA2；调用 `saveAll("certs")` 落盘。
- 用户证书：`Entity::requestCerts(CA&)` 向某下级 CA 申请“加密证书(`id+"_ENC"`, flag2=0)”与“签名证书(`id+"_SIG"`, flag2=1)”，存入证书库。

### 3.6 简易安全邮件系统
- `sendMail(sender, receiver, msg, cipher, log)`：
  1. 查询接收方加密证书链并验证；
  2. 用发送方签名私钥对 `msg` 摘要签名得 `s`；
  3. 组合 `payload = msg + "\n@@SIG@@\n" + s`，打包为 `ZZ`；
  4. 用接收方加密公钥 `encryptMessage` 得到 `cipher`。
- `receiveMail(receiver, sender, cipher, msgOut, log)`：
  1. 用接收方加密私钥 `decryptMessage` 还原 `payload`，按分隔符拆出 `msg` 与 `s`；
  2. 查询发送方签名证书链并验证；
  3. 用发送方签名公钥 `verifyMessage` 验证签名；通过则 `msgOut=msg`。

## 4. 测试与运行结果

编译：`build.bat`（或手动 `g++ -O2 -std=c++11 -o CryptoCourse.exe *.cpp`）。

通过菜单“8. 运行全部测试”得到（512 比特素数，1024 比特同理已单独验证）：

- **RSA**：加解密一致 ✅；签名/验证 ✅；密钥字符串往返一致 ✅。
- **ElGamal**：加解密一致 ✅；签名/验证 ✅；密钥字符串往返一致 ✅。
- **证书方案**：颁发证书（带 `flag1=0, flag2=0`）并验证通过 ✅；篡改 `VER` 后验证失败（防篡改）✅。
- **PKI**：证书库含 3 张 CA 证书；查询 `Alice_ENC` 证书链 `CA_root ← CA1 ← Alice_ENC`，证书链验证通过 ✅。
- **安全邮件**：发送端验证接收方加密证书链通过并加密；接收端验证发送方签名证书链 `CA_root ← CA1 ← Alice_SIG` 通过，签名验证通过，恢复明文与原文一致，邮件收发成功 ✅。

证书已落盘于 `src/certs/`（CA_root.txt、CA1.txt、CA2.txt 等）。

## 5. 使用说明

1. 双击 `build.bat` 编译（或手动用 g++ 编译全部 `.cpp`）。
2. 运行 `CryptoCourse.exe`，根据菜单选择：
   - 1–4：RSA / ElGamal 加解密与签名验证；
   - 5：证书方案（flag1/flag2）；
   - 6：PKI 证书链查询与验证；
   - 7：安全邮件收发演示；
   - 8：运行全部测试；
   - 9：切换密钥强度（512 / 1024，1024 完全符合任务书对 1024 比特素数的要求，耗时更长）。
3. 程序从文件/控制台读取明文与签名消息；大量输入建议以文件方式准备（演示默认内置示例消息）。

## 6. 不足与改进

- 素数为 1024 比特时，Miller–Rabin 轮数与模幂在大整数库下耗时较高；可改用以汇编优化的 GMP/NTL 替换内置 `ZZ` 以提速（接口已兼容）。
- 当前为教学演示，缺少前向安全、证书撤销列表（CRL）与有效期校验，可在 `Cert` 中追加 `NOTBEFORE/NOTAFTER` 字段并在 `verifyCertificate` 中校验。
- 安全邮件未做防重放/顺序号；可补充一次性随机数与时间戳。
