**2. 编程任务 1---简单证书方案**  
实现一个简单的证书方案  
Alice的证书Cert(Alice)格式如下：  
Cert(Alice)=(ID(Alice)||ver_Alice||s||ID(TA)||flag1||flag2)  
其中签名s如下计算：  
s = sig_TA的私钥 (ID(Alice)||ver_Alice)  
ver_Alice表示Alice的公钥，  
flag1标识签名算法，0表示RSA，1表示Elgamal。  
flag2标识公钥用途，0表示加密，1表示签名。  
对应的验证算法不变，即  
ver_TA的公钥 (ID(Alice)||ver_Alice, s)=true 则说明证书可信，否则不可信。

**2. 编程任务 --- 简易PKI系统**  
实现《密码学原理与实践》12.3.1节中的严格层次PKI系统的简易版本，要求如下：

- 包含一个根CA(CA_root)，根CA的证书由自己签名，自己给自己颁发。
- 根CA下有2个下级CA（CA1, CA2），它们的证书由根CA签名和颁发。
- CA1和CA2下是用户。用户证书由CA1或CA2签名和颁发。
- 各个CA生成证书后，把证书存储到证书库中。

**2. 编程任务 --- 简易PKI系统**  
实现一个可公开查询的证书库。该证书库存储了该PKI系统的所有证书。证书库的功能有：

- 只存储CA发来的证书。
- 对任何人提出的查询申请（申请内容为证书所有者的ID），返回证书路径。如Bob发送申请为ID(Alice)，而Alice的证书由CA1颁发，则证书库返回路径为<CA_root的证书，CA1的证书，Alice的证书>

**2. 编程任务 --- 简易PKI系统**  
实现该证书系统的一个使用例子：

- Alice向CA1或CA2申请证书，CA生成Alice的证书，并把Alice的证书存储到系统的证书库中供以后查询。
- Bob向CA1或CA2申请证书，CA生成Bob的证书，并把Bob的证书存储到系统的证书库中供以后查询。
- Eve向CA1或CA2申请证书，CA生成Eve的证书，并把Eve的证书存储到系统的证书库中供以后查询。
- Alice向Bob发送消息和该消息的签名。
- Bob在证书库中查询Alice的证书，证书库向Bob返回Alice的证书路径（或称为证书链）（包含根CA的证书，给Alice颁发证书的CA的证书及Alice的证书）。
- Bob验证Alice的证书路径是否正确，如果正确，则用Alice的证书中的公钥验证Alice发来的签名是否正确。

**2. 编程任务 --- 简易安全邮件系统**  
无需网络传输  
发送端发送邮件过程：

1. 在证书库中查询接收端的加密公钥的证书链，并验证证书链是否正确。如果不正确则根据用户选择再次申请证书链或退出。
2. 用发送端签名公钥对邮件m的hash值签名，得到签名s，hash函数自选。
3. 从步骤1获取的接收端的证书中取出接收端的加密公钥。
4. 用接收端的加密公钥加密m||s，得到密文c。
5. 发送c。

接收端接收邮件过程：

1. 用接收端的加密私钥解密c，得到m||s。
2. 在证书库中查询发送端的签名公钥的证书链，并验证证书链是否正确。如果不正确则根据用户选择再次申请证书链或退出。
3. 从步骤2获取的发送端的证书中取出发送端的签名公钥。
4. 用发送端的签名公钥验证签名是否正确。
